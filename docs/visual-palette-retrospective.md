# 水影笺 v3.5 视觉 Vibe Coding 复盘

日期：2026-09-08  
基线：小红书容器版 `835a9b4`，发布候选 `水影笺_小红书_v1.8.zip`（资源版本 `v3.5`，官方 audit 通过：78 files / 0 warnings）。

## 一句话结论

水影笺的最大坑不是“颜色没调准”，而是把色值当成孤立参数。这里的正确模型是：**一个色盘 = 文化主题 + 固定纸底 + 油墨语义 + 导出 shader + 成笺混合模式 + 装饰层 + 随机度控制 + 验收样张**。少任何一环，就会在别的色盘上复利式反弹。

## 事实基线

| 色盘 | 纸底 / 载体 | 油墨语义 | 成笺技术路线 | 特色层 |
| --- | --- | --- | --- | --- |
| 青绿 | 浅暖宣纸 `#F6EFDC` | 矿物色，减光 | `whiteExport + multiply` | 满铺洒金 |
| 松烟 | 浅暖宣纸 `#F6EFDC` | 五墨分层，显式 `gain` | `whiteExport + multiply` | 满铺洒金、留白 |
| 敦煌 | 生图壁画土墙为纸底 | 岩彩，疏朗注墨 | 纸底 100% 呈现 + 白底墨纹 `multiply` | 土墙、剥蚀、金泥 |
| 汝窑 | 天青釉面 `#A8C4C0` | 青蓝同族明度分层 + 暖色开片呼应 | 花纸开片 + `whiteExport + multiply` | 铁线、金丝 |
| 中秋 | 磁青深蓝 `#0E162E` | 月白粉、泥金粉、发光粉彩 | 保色相导出 + `screen` | 月轮、桂雨、星子 |

## 分工复盘

### zcode / 工程实现

贡献是把流体、拓印、容器适配、功能流程工程化，能快速把审美方案变成可运行代码。主要坑是容易在共享代码里找“万能改法”：改一个材质、一个 shader 分支或一个回滚，试图同时解决多个主题，结果造成交叉影响。之后凡是共享文件，都要先画出影响面，再动手。

以后交给工程 agent 的任务应该写成：目标色盘、允许改动文件、禁止改动的共享语义、预期截图、回归色盘清单。不要只写“把敦煌调亮”。

### Kimi / K老师：审美与诊断

贡献是把问题从“颜色不好看”推进到材质语义：磁青纸要用粉彩和 screen，敦煌土墙要成为纸底而不是装饰贴图，汝窑要用天青花纸和铁线 / 金丝开片。v3.5 的汝窑重配、中秋保色相、桂花和星子加密也来自这条思路。

踩过的坑有两类。一是早期方案偏“加层”：透明度、滤镜、三层拆解、浮层都能讲出理由，但混合后容易脏，最终敦煌和汝窑都回到更清晰的“花纸”结构。二是审美 agent 中断时改动已落盘但验证未闭环，接手者不能相信“改了就等于改对了”。

以后审美 agent 的输出必须包含：参考图、纸底路线、色角色分层、最小 / 最大使用面积、失败样式、期望成品样张。审美判断可以主观，验收标准必须可执行。

### Codex / 收尾验证

这轮有效的工作方式是先找当前事实：git 历史、组合锁定、shader 分支、容器审计、真实样张，再只修当前问题。也发现文档过期会造成下一次误判，因此收尾必须同步 README / AGENTS / decisions，而不是只提交代码。

## 核心经验

1. **纸底是主动变量。** 浅宣纸、土墙、釉面、磁青分别决定油墨的加光 / 减光、颗粒密度和装饰语法。先定纸，再定墨。
2. **色号只在最终载体上成立。** `#D9AD4D` 在白底、土墙、天青、磁青上的意义不同；验收永远看成笺，不看 picker。
3. **回滚要带回上下文。** 逐字节回退一个主题路径可以救命，但必须核对 schema、shader 分支、资源版本和依赖字段，否则会引入全黑或缓存旧码。
4. **随机美感要变成可测指标。** 洒金、桂花、星子、开片都随机；至少用固定 seed / demo 钩子 + 3 张样张，统计可见颗粒数量、亮度和分布。
5. **视觉修 bug 先问路径。** 屏幕显示、墨池、导出、成笺、保存、容器回显不是同一条链路；先定位哪一层，再改色。
6. **UI 也是视觉资产。** 成笺 / 素笺按钮要用 flex 居中和稳定高度，不要靠 line-height 猜；中文大字要预留字体行高。
7. **性能是审美的一部分。** 纹理、FBO、粒子过多会掉帧；离线包要控制在预算内，随机装饰先定视觉阈值，再定数量。
8. **容器合规优先于代码优雅。** 禁网络、禁下载、CSP、旧 WebView 都不是重构建议，而是发布红线。

## 新色盘 SOP

1. **立意**：写 80 字主题 brief，明确文化对象、季节 / 场景、克制原则、不可使用的俗套元素。
2. **定纸**：先给纸底小样和物理语义（宣纸 / 壁面 / 釉面 / 深色笺 / 织物等），决定它是浅底减光还是深底加光。
3. **定墨**：7 色左右，分主色、过渡、水光、点睛、禁忌色。主色与纸底的明度差要足够；深底色盘先保证色相不被洗白。
4. **定装饰**：只选 1 个主题装饰 + 1 个材质颗粒，写密度、尺寸、分布和最小可见数。不要每个想法都叠一层。
5. **定路线**：在组合契约表登记 `material / paper / paperImg / whiteExport / blend / damp / gain / shader branch / pattern`，明确哪些字段专属该盘。
6. **做样张**：同一色盘至少 3 个 seed，覆盖满铺、疏朗、点睛三种玩法；保留 1 张“黄金样张”和 1 张“失败样张”。
7. **隔离实现**：新增字段先扩 schema，再改渲染；公共材质只放真正共享的物理语义，主题特有逻辑挂在 suite key 下。
8. **回归既有色盘**：新色盘合入前，青绿、松烟、敦煌、汝窑、中秋各出 1 张导出样张；如果改 shader，则每盘都看导出图，不只看当前屏。
9. **容器验证**：跑官方 audit、系统 Chrome 视觉验收、真机保存 / 发笔记 / 回显；确认无网络请求和下载残留。
10. **发版闭环**：升级两仓资源版本，重打 zip，记录 decisions，更新 README / AGENTS，再提交推送。

## Web 视觉艺术类作品路径

适合之后做同类 vibe coding 时直接复制：

1. **主题想象**：先写审美故事和“不像什么”，避免功能堆叠。
2. **物理模型**：确定载体、材料、光照、笔触、扩散、沉淀、颗粒、时间感。
3. **最小可感原型**：一张静态成品目标图优先；先让眼睛相信，再工程化。
4. **分层契约**：纸底、主画面、材质、装饰、文字、边框、导出层逐层命名，禁止跨层魔法数。
5. **算法与随机**：把随机参数集中在可复现配置里，用 seed 和 demo 钩子调试。
6. **视觉门禁**：shader 编译日志、样张截图、像素采样、颗粒计数、文字 / 按钮布局检查。
7. **交互完整度**：入口、切换、保存、回看、失败态、空态、性能降级一起验收。
8. **平台收敛**：离线、CSP、旧内核、包体、JSBridge、真机路径最后统一过一遍。
9. **发布叙事**：同时产出发布包、 changelog、示例图和下一轮待办；用户看到的是作品，维护者看到的是契约。
